    Built to be verifiable

    RAG written from first principles, with the failure modes engineered out.

    Citations that cannot hallucinate

    The model only sees [Passage N] labels. Page numbers and titles come from the metadata store, never from the model. Out-of-range tags are dropped before rendering.

    No orchestration frameworks

    Extraction, chunking, embedding, indexing and prompting are plain, inspectable Python on top of PyMuPDF, sentence-transformers and FAISS. No LangChain.

    Grounded or refused

    Below a similarity threshold the system refuses instead of guessing. Prompt-injection text inside a PDF is treated as data, never as instructions.

    Defensive by default

    Uploads pass extension, magic-byte, corruption and extractable-text checks. Metadata persists as JSON, not pickle, so a tampered file cannot execute code.

    How it works

    Two deterministic pipelines: offline indexing, online answering.

    1. 1

      Upload

      Your PDF is validated and hashed with SHA-256, so the same file is never indexed twice.

    2. 2

      Chunk & embed

      Pages are split on sentence boundaries into ~200-token windows with overlap, then embedded with all-MiniLM-L6-v2.

    3. 3

      Retrieve

      Your question is embedded the same way and FAISS returns the closest passages by exact cosine similarity.

    4. 4

      Answer with receipts

      Gemini answers only from those passages. Citations resolve back to the document name and page number.
